# 커밋 생성

## 인자

`/commit SESAC-123`처럼 티켓 ID를 넘길 수 있다. 넘긴 값은 브랜치명보다 우선한다.
인자가 없으면 브랜치명에서 찾고, 그것도 없으면 사용자에게 요청한다.

커밋을 여러 개로 나눌 때 티켓이 서로 다르면 인자 하나로는 표현할 수 없다.
이때는 덩어리 목록을 보여주고 덩어리별 티켓 ID를 사용자에게 받는다.

## 절차

1. `git status --short`와 `git diff --staged`로 변경 내용을 확인한다.
   스테이징된 것이 없으면 무엇을 스테이징할지 사용자에게 묻는다.
   임의로 `git add .`를 실행하지 않는다.
2. 커밋을 여러 개로 나눌 것 같으면 덩어리 구성을 먼저 제안하고 합의한다.
3. `workbench/linear-ticket.md`를 열어 오늘 날짜 섹션을 확인한다.
   없으면 문서 맨 위에 만들고, 파일 자체가 없으면 새로 만든다.
   덩어리별로 표에 행을 추가하고, 문서 하단에 티켓 상세를 작성한다.
   형식은 CLAUDE.md의 "티켓 대장"을 따른다.
   이 파일은 Git에서 제외되므로 커밋 대상 목록에 넣지 않는다.
4. 덩어리마다 티켓 ID를 정한다.
   - 대장에 번호가 채워져 있거나 사용자가 알려줬으면 그 값을 쓴다.
   - 없으면 `git rev-parse --abbrev-ref HEAD`로 브랜치명에서 `sesac-<숫자>`를
     찾아 대문자로 바꿔 쓴다.
   - 둘 다 없으면 커밋하지 말고 멈춘다. 대장에 적은 티켓 상세를 보여주면서
     Linear 이슈를 만들어 번호를 알려달라고 요청한다.
     사용자가 티켓 없이 진행하라고 한 경우에만 티켓 ID 없이 작성한다.
5. CLAUDE.md의 커밋 컨벤션에 맞춰 메시지 초안을 작성한다.
6. 커밋 전에 메시지 전문을 보여주고 사용자 승인을 받는다.
7. 승인되면 덩어리별로 스테이징해 순서대로 커밋한다.
8. 커밋한 행의 상태를 `☑`로 바꾼다. 대장은 Git 제외 대상이라 커밋하지 않는다.

## 주의

- 변경의 "왜"를 확신할 수 없으면 추측하지 말고 사용자에게 묻는다.
- 관련 없는 변경이 섞여 있으면 커밋 분리를 먼저 제안한다.
- `git push`는 자동으로 실행하지 않는다.
