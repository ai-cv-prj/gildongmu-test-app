# 신호등 모듈: SESAC-73

2026-09-21 기준 구현과 검증 기록입니다. 검출 실패와 안내 대상 선택 실패를 구분하고, 처음 선택한 신호등이 계속 보이는 상황에서도 횡단보도 연결 근거에 따라 대상을 바꿀 수 있도록 개선했습니다.

## 처리 흐름

1. YOLO가 보행자 신호등과 횡단보도를 검출합니다. 앱 검출 기준을 통과한 박스를 모두 응답에 포함합니다.
2. 이전 대상이 있으면 현재 검출과 위치·크기를 비교합니다. 신뢰할 수 있는 카메라 이동 추정이 있으면 이전 박스 좌표를 먼저 보정합니다.
3. 추적 대상이 없을 때 신호등이 하나면 바로 선택합니다. 여러 개면 횡단보도 선택 → 줄무늬 방향 추정 → 방향에 맞는 신호등 후보 선정 → 같은 신호등·횡단보도 3프레임 연속 확인을 거칩니다.
4. 추적 대상이 현재도 보이고 신호등이 여러 개면 횡단보도 연결을 다시 검사합니다. 다른 후보가 나오면 기존 색상 출력을 보류하고, 같은 연결을 3프레임 연속 확인한 뒤 대상을 변경합니다.
5. 최종 선택된 현재 프레임의 신호등만 크롭해 MobileNet으로 색상을 분류합니다. 선택 보류 중에는 `unknown`을 반환합니다.

단순 최고 검출 신뢰도 선택이나 모든 신호등의 가중합 순위 기반 다중 객체 추적은 사용하지 않습니다. `track_id`는 세션 내 안내 대상의 식별자입니다.

추적 대상 소실이나 매칭 모호 시에도 기존 상태를 지우고 새로 선택합니다. 초기화 후 신호등 하나만 보이면 즉시 선택할 수 있습니다.

다른 후보를 확인 중이면 `waiting_for_target_switch`, 변경 확정이면 `target_switched`와 새 `track_id`를 기록합니다. 기존 대상이 다시 연결되더라도 충돌 이후에는 3프레임 확인이 필요하며, 이때는 `waiting_for_target_revalidation` → `target_revalidated`로 기존 번호를 유지합니다. 후보나 횡단보도가 바뀌거나 연결 근거가 끊기면 연속 확인을 초기화합니다.

방향 후보가 모호하거나 방향에 맞는 신호등이 없으면 색상을 보류합니다. 이처럼 연결 충돌이 발생한 뒤에는 횡단보도 미검출·방향 추정 실패·단일 검출만으로 색상을 복구하지 않습니다. 반면 아직 충돌이 없고 단순히 횡단보도나 방향을 찾지 못한 경우에는 현재 검출된 기존 대상을 유지합니다.

## 방향 추정과 흔들림 보정

`traffic_geometry.py`는 횡단보도 박스 안에서 밝고 긴 도색 줄무늬를 추출하고 양 끝점으로 경계선을 맞춰 교점을 추정합니다. 각 경계선은 최소 3개 줄무늬의 지지가 필요합니다. 화면·박스 경계에 잘린 끝점, 평행하거나 불안정한 교점, 근거가 비슷한 서로 다른 방향은 제외합니다. 기존 Hough 교점 투표 경로를 교체했으며, 기존 경로의 `numpy.int32` 좌표 처리 오류도 해당 경로 제거로 해소했습니다.

`traffic_motion.py`는 이전·현재 프레임의 특징점에 왕복 광류 검사와 RANSAC을 적용합니다. 최소 16개 일치점, 65% 이상 일치 비율과 화면 내 분포 조건 등을 통과한 이동만 이전 대상과 연속 확인 후보의 좌표 보정에 사용합니다. 실패하면 원래 좌표로 비교합니다. 검출 모델의 입력 영상을 안정화하는 기능이 아니며, 사라진 박스나 과거 신호색을 복원하지 않습니다.

## 화면과 저장 결과

미선택 신호등은 파란색, 확인 중인 후보는 노란색, 최종 대상은 굵은 박스와 안내 대상 문구로 구분합니다. 횡단보도는 보라색, 연결 판단에 사용된 횡단보도는 청록색입니다. 청록색은 연결 성공을 보장하지 않습니다. 실시간 화면·저장 영상·모델 점검 이미지에 횡단보도 박스와 탈락 사유를 표시합니다.

| 필드 | 의미 |
| --- | --- |
| `detections` | 신호등 뒤에 횡단보도를 추가한 전체 박스 목록 |
| `event.selected_detection_index` | 최종 선택 박스의 현재 `detections` 인덱스; 미확정 시 null |
| `event.candidate_detection_index` | 확인 중인 신호등 후보 인덱스 |
| `event.detected_signal_count` | 신호등 개수; 전체 박스 개수와 구분 |
| `event.crosswalk_candidate_count` | 표시 가능한 횡단보도 후보 수 |
| `event.detected_crosswalk_count` | 연결 신뢰도 0.50 이상 횡단보도 수 |
| `extra.crosswalk_status` | `below_confidence` / `position_rejected` / `eligible` / `used` |
| `extra.exclusion_reasons` | `below_confidence` / `bottom_too_high` / `off_center` 목록 |
| `event.crosswalk_diagnostics` | 검출·연결 상태, 후보·기준 통과 수, 사용된 횡단보도 인덱스 |
| `event.selection_origin` | 단일 검출 `single_signal` 또는 연속 연결 확인 `crosswalk_matched` |
| `event.tracking` | 매칭 근거, `camera_motion`, 재검사 상태·사유, `target_change` |

신뢰도 0.50 미만이거나 위치 조건에서 탈락한 횡단보도도 표시하지만, YOLO 검출 기준에서 이미 제거된 후보는 표시하지 못합니다. `selection_origin=single_signal`인 대상을 추적했다는 사실만으로 횡단보도 연결이 검증되지는 않습니다.
